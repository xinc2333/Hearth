# 世界玩法设计

本文是「世界」玩法的设计稿：在固定的一座城市澜江市里，由数值和规则推动日常生活和事件。它建在跑团之上（见[跑团设计](tabletop.md)）。目前还没有实现，实现后按现状改写。

## 0. 目标和原则

- **像一座自己会运转的城市。** 时间会走，人有工作和作息，钱会花完，约好的人会等你，不回消息会有人找。玩家只管扮演主角。
- **数值驱动事件，事件驱动数值。** 规则根据时间和数值产生事件，例如「上班时间到了，你不在公司」；事件发生后，结算按跑团的规则改数值，例如上司对你的信任下降。每一处变化都记下缘由。
- **程序算，模型写。** 时间、路程、车费、工资、作息、谁在哪里，都由程序计算。模型只做两件事：把事实写成剧情；结算时报告剧情里发生了什么。
- **只给模型看眼前的。** 城市、人物和事件都按「和这一幕有没有关系」挑选。交给模型的数据有多长，取决于这一幕，不取决于城市有多大、玩了多久。
- **不增加每轮的请求次数。** 仍是跑团的三步：裁定、叙述、结算。世界的数据接在每一步的末尾，不在场的人怎么过也并进结算。
- **城市只有一座。** 澜江市由 Hearth 自带，地点、交通和地图都是写好的数据。剧情里出现的新地点会登记进去。
- **沿用跑团。** 属性、特长、状态、别人对主角的态度、结算，都照跑团的规则。世界只增加时间、地点、钱、作息和规则。

## 1. 一轮怎么跑

```
你发消息
  │
第一步：裁定（跑团的裁定 + 这一轮的时间）
  │  模型除了列出检定，还要估计这一轮过去多久、主角去不去别处、怎么去
  ├─ 程序算路线、用时和车费，定下这一轮的时间段，例如 07:30 → 08:40
  ├─ 程序把这段时间里的规则跑一遍：上班、约定、消息、不在场的人的作息……得出这一轮的事件
  │
第二步：叙述
  │  模型按检定结果和这一轮的事件写正文，一直写到时间段的结尾
  │
第三步：结算（在后台进行）
  │  跑团的结算，加上世界的部分：钱的收支、约定、联系方式、新地点、比计划多出的时间；
  │  跨过了一天时，顺带写不在场的重要人物这一天的近况
  │
程序记账：时间、位置、钱、事件记录和各项数值，存进这个回复版本
```

- **时间以裁定定下的时间段为准。** 剧情比计划走得更远时（例如主角睡着了），结算可以往后推，多出的时间里产生的事件放到下一轮。时间不会往回退。
- **单轮上限**：不是跳过时间时（第 4 节），一轮最多 3 小时。
- **换一版回复、继续写**：沿用这一轮的裁定，时间段和事件不变。
- **开着「检定绝对通过」**：没有裁定，这一轮的时间由结算报告，事件放到下一轮。
- **聊天模式**（直接和 AI 聊天）：整轮不跑跑团，也不跑世界。

## 2. 开局

「澜江市」是 Hearth 自带的一张角色卡，出现在角色卡列表里，带「世界」标签。在它上面新建对话时，先出现开局页：

| 项 | 说明 |
| --- | --- |
| 名字 | 默认用当前用户角色的名字 |
| 性别、年龄 | |
| 职业 | 上班族、学生、自由职业、无业，再写一句具体做什么，例如「广告公司的设计」 |
| 住在哪 | 选一个区，或者交给程序按职业和收入挑 |
| 关于主角 | 外貌、性格、经历，随便写，可以不写 |
| 开始时间 | 默认 2026-03-02（星期一）07:30 |

点「生成」后，Hearth 发一次请求，强制调用 `hearth_setup`。模型按上面的内容写出：

- 属性和特长（按跑团的参照表）
- 单位、职位、月薪和班次（上班族），或者学校和课表（学生）
- 住处和房租，或者自有住房
- 余额和生活水平
- 上司和两位同事（上班族），或者辅导员和两位同学（学生），作为普通 NPC
- 一两位家人，作为普通 NPC，住在城外的只记名字和关系

结果显示在开局页上，可以改，点「开始」进入对话。

- 主角的介绍存成这个对话专用的用户角色，对话绑定它，不影响别的对话。
- 当前预设还没有跑团和世界的条目时，「开始」会顺带加上，页面上写明这一点。
- 对话的第一条消息由程序写：第几天、日期时间、天气、在哪、今天的安排。从你的第一句行动开始，交给模型。
- 生成主角的说明是 Hearth 自带的，不来自预设。这和编辑模式的改卡说明一样，不属于剧情提示词。

## 3. 澜江市

### 概况

| 项 | 内容 |
| --- | --- |
| 定位 | 架空的中国东南沿海城市。澜江自西向东穿城入海，把市区分成江北和江南 |
| 人口 | 常住约 310 万 |
| 范围 | 地图东西约 42 km，南北约 30 km，面积约 475 km²（含西部山区） |
| 气候 | 亚热带季风。春季多雨，6 月梅雨，7～9 月有台风，冬季湿冷，最低约 0°C |

### 区

| 区 | 位置 | 有什么 | 人口 |
| --- | --- | --- | --- |
| 月湖区 | 江北西部，老城 | 月湖、钟楼街和老街巷、市政府、老小区、菜市场、老字号 | 约 60 万 |
| 江湾区 | 江北东部，新城 | 写字楼和金融街、大型商场、江景高层、会展中心、高铁澜江站 | 约 70 万 |
| 南岸区 | 江南 | 澜江大学和大学城、中学、成片的居民区、夜市、科技园、体育中心 | 约 100 万 |
| 港城区 | 东部入海口两岸 | 港口和物流园、渔港和海鲜市场、金沙滩、工业区，东北方向是机场 | 约 45 万 |
| 苍山区 | 西部山麓 | 苍屏山、寺庙、茶园、民宿、植物园、水库、别墅区 | 约 35 万 |

### 自然地理

- **澜江**：市区段约 30 km，江面宽 300～600 m，入海口宽约 1.5 km，受潮汐影响。
- **白沙洲**：澜江中游的江心洲，有公园、美术馆和轮渡码头。
- **月湖**：老城中心的湖，面积约 1.2 km²，环湖步道约 5 km。
- **青溪**：从苍屏山流下，在月湖区西南汇入澜江。
- **苍屏山**：城西的山，主峰望澜峰海拔 706 m，有登山道和索道。
- **澜湾**：城东的海湾，有金沙滩和渔港。

### 交通

| 方式 | 内容 |
| --- | --- |
| 地铁 1 号线 | 东西线：苍山区植物园站 → 月湖区 → 江湾区 → 港城区港城站，21 站 |
| 地铁 2 号线 | 南北线：江湾区澜江站（高铁）→ 江湾中心 → 过江隧道 → 南岸区大学城站，15 站 |
| 地铁 3 号线 | 滨江线：南岸区科技园站 → 沿江南岸 → 港城区金沙滩站，16 站 |
| 地铁运营 | 6:00～23:00，高峰 3～4 分钟一班，平时 6～8 分钟一班，票价 2～7 元 |
| 公交 | 约 150 条线路，2 元；22:00 以后只有夜班车 |
| 出租车、网约车 | 起步 10 元（3 km），之后 2.4 元/km，23:00～5:00 加价 20% |
| 过江 | 澜江一桥（月湖—南岸）、澜江二桥（江湾—南岸）、海湾大桥（港城两岸）、江湾隧道；轮渡：月湖码头—白沙洲—南岸码头，6:30～21:00，20 分钟一班 |
| 对外 | 高铁澜江站（江湾区）、普速澜江老站（月湖区）、澜江机场（港城区东北，离市中心约 30 km）、长途汽车站（南岸区） |

### 地点

地图上有约 120 个写好的地点。每个地点记下名字、所属区、坐标、类型、营业时间和一句话简介。

| 类型 | 例子 |
| --- | --- |
| 住处 | 老小区、新小区、城中村、江景公寓、别墅区 |
| 工作 | 写字楼、科技园、工厂、港口、商店、医院、学校 |
| 生活 | 菜市场、超市、便利店、银行、派出所 |
| 吃喝 | 餐馆、小吃街、夜市、咖啡馆、酒吧 |
| 玩 | 公园、景点、商场、电影院、体育馆、海滩 |
| 交通 | 地铁站、车站、码头、机场 |

- 剧情里出现地图上没有的地点（例如老街上一家书店），结算把它登记为新地点，放在最近的已知地点旁边，地图上随之出现。
- 大的地点可以分区，例如「澜江大学 · 图书馆」「星衡广告 · 12 楼」。同一地点的分区之间不算路程。

## 4. 时间

- **精度**：分钟。界面上显示「第 3 天 · 3 月 4 日 星期三 08:15」。
- **怎么走**：只在你发消息时往前走（第 1 节）。没有实时的钟，关掉 Hearth 后世界不会自己运转。
- **跳过时间**：在剧情里直接说「睡到明早 7 点」「接下来一周照常上班」。程序逐天快进，每天照常跑规则和不在场的推演，最后让模型写一段概述。一次最多跳 30 天。快进期间主角按自己的作息过（照常上班、回家），除非你另有说明。
- **天气**：程序按月份的气候每天抽一次天气（晴、多云、阴、小雨、大雨、雷阵雨、雾、台风）和气温，提前生成 3 天，手机里能看预报。
- **一时情绪的回落**：跑团里每轮回落 15%。世界里改为按游戏时间，每小时回落 3%，大约一天回落一半。

## 5. 地点和移动

- **位置**：每个人都有位置。主角精确到地点；重要人物按作息和剧情（第 7 节）；普通 NPC 只记最后见到的地方，以及常出现的地点（例如咖啡馆的店员）。
- **移动**：主角要去别处时，裁定里写目的地和方式，程序按下表算用时和费用。

| 方式 | 用时 | 费用 |
| --- | --- | --- |
| 步行 | 直线距离 × 1.3 ÷ 4.5 km/h | 0 |
| 骑车 | 直线距离 × 1.3 ÷ 12 km/h，加 3 分钟取车 | 每 30 分钟 1.5 元 |
| 地铁 | 走到最近的站 + 等车（半个发车间隔）+ 每站 2.5 分钟 + 每次换乘 5 分钟 + 出站走到目的地 | 按里程 2～7 元 |
| 公交 | 打车用时 × 1.8，加等车 8 分钟 | 2 元 |
| 打车 | 等车 5 分钟 + 直线距离 × 1.4 ÷ 车速（高峰 18 km/h，平时 28 km/h，夜间 40 km/h） | 按计价规则 |
| 开车 | 同打车，不用等车，加停车 5 分钟 | 每公里 0.6 元 |

- 没写方式时，程序按常理挑：1 km 以内步行，地铁运营时坐地铁，深夜打车。
- 地铁停运的时间里不能选地铁。
- 同行的在场角色跟着一起移动。
- 车费自动从余额里扣，记进账目。

## 6. 人

### 每个人有什么

| 数据 | 主角 | 重要人物 | 普通 NPC |
| --- | --- | --- | --- |
| 属性、特长、状态 | 有（跑团） | 有 | 有 |
| 身份和职业 | 有 | 有 | 一句话 |
| 位置 | 精确到地点 | 按作息和剧情 | 最后见到的地方 |
| 钱 | 余额、固定收支、欠款 | 经济状况和月收入 | 经济状况 |
| 工作 | 单位、班次、工资、出勤 | 单位和班次 | 无 |
| 作息和约定 | 班次和约定 | 每周作息和约定 | 无 |
| 近况数值 | 无 | 心情、压力 | 无 |
| 对主角的态度 | — | 有（跑团） | 有（跑团） |
| 对其他人的态度 | — | 只对其他重要人物 | 无，关系用一句话（跑团的 `bonds`） |
| 档案 | 开局时的介绍 | 按模板的完整档案和摘要 | 无 |

- **经济状况**分五档：拮据、紧张、普通、宽裕、富有。重要人物和普通 NPC 只记档位，不记具体余额。
- **主角没有对别人的态度**，和跑团一样，由玩家在剧情里表达。
- **重要人物之间的态度**用跑团的六条线加熟悉度，分方向记（A 对 B、B 对 A 各一份）。只在两人互相认识时建立，只在结算里受到影响时更新：两人同在一幕里经历了一件事，或者不在场时一起出现在某件事里。

### 主角的钱

- **余额**：手机支付和银行卡合在一起算。现金很少用到，不单独记。
- **固定收入**：工资（月薪、发薪日），或者学生的生活费。
- **固定支出**：房租（每月 1 日），每日基本开销（吃饭和日用，按生活水平每天 40、70 或 150 元，每天 0 点扣）。
- **其他收支**：车费由程序扣；剧情里值得一提的花销和收入（请客、买礼物、接了一单活）由结算记下。
- **余额不够**：买不起的东西在剧情里买不成。房租交不上时记为欠款，按第 8 节催租。

### 主角的工作

开局时选一种，规则随之不同：

| 职业 | 作息 | 收入 |
| --- | --- | --- |
| 上班族 | 工作日固定班次，例如 9:00～18:00 | 月薪，每月 10 日发上个月的 |
| 学生 | 工作日上课，例如 8:00～16:30 | 每月 1 日家里转生活费 |
| 自由职业 | 没有固定作息 | 结算记下接到的活和收入 |
| 无业 | 没有 | 没有固定收入 |

剧情里换工作、被辞退、找到新工作，都由结算记下，程序随之换规则。

## 7. 重要人物

### 名额

最多 8 位。满了以后要先取消一位，才能再设一位。

### 怎么产生

- **从剧情里升级**：在「人物」页或地图上，给遇到过的人点「设为重要人物」。
- **新建**：写一段介绍，或者贴进已有的人物档案，也可以从已导入的角色卡里选一个角色。贴进来的档案原样保留，模型只补程序要用的部分。

升级或新建时，Hearth 发一次请求：最近一轮回复的请求，加上预设里的「世界·人物档案说明」，强制调用 `hearth_profile`。模型按这个人在剧情里已有的表现写出：

- 按模板的完整档案（2000～3000 字）和摘要（150～250 字）
- 属性、特长、性格系数（已有的保留）
- 住处和工作单位：从地图上选，或者登记新地点
- 每周作息
- 经济状况和月收入
- 和其他重要人物的初始态度（认识的才写）

结果直接生效，可以在「人物」页修改，或者点「重新生成」。

### 档案模板

| 部分 | 内容 |
| --- | --- |
| 基本信息 | 姓名、年龄、性别、身份 |
| 外貌 | 身高体型、发型、五官和标志性特征、不同场合的穿着 |
| 背景 | 出身、教育、经历、现在的生活和经济 |
| 兴趣爱好 | 喜欢做什么，做到什么程度 |
| 人际关系 | 家人、朋友、和其他重要人物的关系 |
| 语料 | 几组问答，展示他怎么说话。只作参考，不是发生过的事 |
| 性格 | 底色、主色调、点缀、对冲四层，每层几条衍生和一条反向衍生 |
| 理解 | 这些性格怎样切换和共存、行为的边界、在什么条件下露出哪一面、和主角相处的原则 |

性格分四层、另写一段「理解」，是为了让模型把人演成几种特质的组合，而不是一个标签。

### 取消

取消重要人物后，档案保留，以后再设为重要人物时不用重写。他不再推演，地图上不再显示。他和其他重要人物之间的态度保留，但不再更新。

### 不在场时怎么过

由程序计算，不调用模型：

- **位置**：按每周作息走（上班、回家、常去的地方），有约定时按约定走。剧情把他带到别处时，以结算为准，直到作息切换到下一段。
- **心情**（0～100，平常 50）：每天往平常值回落一半，再加上事件的影响。
- **压力**（0～100）：上班日 +5，休息日 −10，再加上事件的影响。
- **生活事件**：每天按事件表抽 0～2 件，例如加班、被上司批评、和朋友聚会、失眠、生病、买到想要的东西。概率随心情、压力、经济状况和性格调整。
- **重要人物之间的交集**：互相认识、亲近不低的两个人，同时有空时有机会见面，算一件事件。
- **要不要联系主角**：见第 8 节「主动联系」。

调用模型的只有一处：跨过一天的那一轮结算里，把这一天有事发生的重要人物交给模型。模型给每人写一句近况，并按事件给出心情、压力和他们彼此态度的变化。没事发生的人不写。

## 8. 规则

程序在每一轮的时间段里检查规则，满足条件就产生事件。事件交给模型写进剧情；后果由程序执行，涉及态度的交给结算。

### 第一期的规则

| 规则 | 条件 | 事件和后果 |
| --- | --- | --- |
| 迟到 | 工作日上班时间到了主角不在单位，2 小时内到了 | 记一次迟到，扣 50 元，上司知道；过了 30 分钟还没到时，同事先发消息问 |
| 旷工 | 上班时间过了 2 小时仍没到，也没请假 | 扣当天工资（月薪 ÷ 21.75），上司打电话 |
| 警告和辞退 | 连续旷工 2 天；30 天内累计旷工 3 天 | 上司警告；辞退，工作清空 |
| 请假 | 结算记下请假 | 事假扣当天工资，病假扣一半，不算旷工 |
| 逃课 | 学生上课时间不在学校 | 辅导员或同学发消息 |
| 发工资、生活费 | 每月 10 日、1 日 | 余额增加，工资扣掉迟到、旷工和事假 |
| 房租 | 每月 1 日 | 扣房租；不够时记欠款，3 天后房东催，15 天后上门，30 天后要求搬走 |
| 基本开销 | 每天 0 点 | 按生活水平扣钱 |
| 熬夜 | 主角连续清醒超过 18 小时；超过 30 小时 | 加状态「困倦」（全部属性 ×0.9）；改为「极度疲惫」（×0.7）；睡够 6 小时后去掉 |
| 约定 | 到了约定时间，主角不在约定地点 | 15 分钟后对方发消息；45 分钟后对方离开，记一次爽约 |
| 主动联系 | 见下文 | 重要人物发消息或打电话 |

### 主动联系

每位重要人物每天抽一次，联系主角的概率：

> 概率 = 熟悉 ÷ 100 ×（亲近 + 吸引 × 0.5）÷ 100 × 距上次联系的天数 × 0.5 + 事件加成

| 情况 | 加成 | 他想说什么 |
| --- | --- | --- |
| 心情很差（低于 30），信任主角（60 以上） | +0.3 | 想找人说说 |
| 心情很好（高于 75），亲近主角（50 以上） | +0.2 | 想分享 |
| 怨恨主角（60 以上），最近起过冲突 | +0.2 | 质问 |
| 24 小时内有约定 | 一定联系 | 确认或提醒 |

- 例：熟悉 80、亲近 60、吸引 40，一天没联系时概率约 32%，两天约 64%。
- 概率最高 90%；每人每天最多主动联系 2 次。
- 只能联系存了主角联系方式的人（第 9 节）。
- 联系的时间挑在他作息里有空的时段。
- 内容由模型在那一轮的正文里写：主角看到消息、接到电话。主角睡着或在忙时，消息留在手机里。

规则写在代码的规则表里，数值参数（扣多少钱、几小时算旷工、概率系数）放在插件设置里，可以调。更多规则见第 15 节。

## 9. 手机

- **联系人**：剧情里交换过联系方式的人，由结算记下。开局生成的上司、同事和家人自带。
- **消息**：时间、谁、内容摘要、有没有回。内容来自正文，由结算记下。保留最近 100 条。
- **日程**：今天的班次和约定，以后的约定。
- **天气**：今天和之后两天。

## 10. 交给模型的数据

世界的数据按「这一幕需要什么」挑选，接在跑团数据后面：

| 内容 | 裁定 | 叙述 | 结算 | 约多少字 |
| --- | --- | --- | --- | --- |
| 时间、天气、主角所在的地点 | 有 | 有 | 有 | 100 |
| 这个地点的简介、营业情况、常在这里的人、附近的地点 | 有 | 有 | 有 | 250 |
| 主角的钱、工作、今天的安排和约定 | 有 | 有 | 有 | 150 |
| 这一轮的时间段和事件 | — | 有 | 有 | 0～400 |
| 未读的消息 | 有 | 有 | 有 | 0～200 |
| 在场的重要人物 | 摘要 | 完整档案 | 沿用叙述的请求 | 每人 200 / 2000～3000 |
| 在场的重要人物彼此的态度 | 有 | 有 | 有 | 每对 60 |
| 不在场的重要人物：在哪、在做什么、近况 | 有 | 有 | 有 | 每人 40 |
| 跨过一天时，不在场的重要人物这一天的事件 | — | — | 有 | 每人 100 |

- **城市概况**（约 800 字）写在「澜江市」这张角色卡的描述里。它每轮不变，能用上缓存。
- **地图**只给你看，不发给模型。
- **规则和账目**留在程序里，模型只看到结果，例如「今天旷工，扣了 290 元」。
- **主角不知道的事**（不在场的人的近况、别人背后做的事）在数据里标出「主角不知道」。叙述说明要求只通过主角看得到、听得到的方式体现，和暗骰一样。
- **正文里不出现数字**：和跑团一样，时间、钱这类数值可以自然地写（「快九点了」「打车花了三十多」），属性和态度的数值不写。

## 11. 费用

**每轮的请求次数不变，仍是三次。** 世界只让每一步的末尾多一些数据：

- 不算在场重要人物的档案，每一步多约 800～1300 字。
- 在场的重要人物，只有叙述那一步带完整档案，每人 2000～3000 字。结算接在叙述的请求后面，这部分能用上缓存。
- 跨过一天的那一轮，结算再多约 100 字 × 有事发生的重要人物数。

一次性的请求：

- 开局生成主角：一次，不带预设和聊天记录。
- 设为重要人物：每位一次，接在最近一轮的请求后面，能用上缓存。

省钱的做法：

- **变动的内容只放在末尾。** 放在聊天记录前面的内容一变，整段聊天记录的缓存就失效了，所以世界的数据都接在请求末尾。
- **推演按游戏天，不按轮。** 没事发生的人不写。
- **普通 NPC 不推演。** 遇到了才登记，只记最后见到的地方。
- **快进只写一段概述。** 程序逐天算，模型最后只写一次。

对照：如果每轮给每位重要人物单独发一次请求，8 位重要人物就是每轮多 8 次完整的请求。

## 12. 界面

- **状态条**：输入框上方一行，例如「第 3 天 · 3 月 4 日 星期三 08:15 · 小雨 · 南岸区 翠湖小区 · 余额 4,230 元」。
- **事件条**：回复上方，和检定条放在一起，例如「09:00 上班时间到了，你不在公司」。点开看详情。
- **结算提示**：回复下方，在跑团的基础上加上世界的变化，例如「余额 −36 元（打车）」「到达 月湖区 钟楼街」「新约定：周五 19:00 和林晚在小酌酒馆」。
- **检查器新增三页**：
  - 「地图」：能缩放、拖动的示意地图，画出区、江湖海、山、地铁线和地点，标出你、重要人物和约定的地点。点地点看简介，点人看位置和近况。
  - 「人物」：重要人物（位置、近况、档案、彼此的态度）和遇到过的人，以及「设为重要人物」「取消重要人物」「新建重要人物」。
  - 「手机」：联系人、消息、日程、天气预报。
- **开局页**：见第 2 节。
- 界面上不用表情符号，地图上的地点用简单的图形区分类型。

## 13. 实现

### 放在哪里

世界是跑团插件里的一个模式，代码放在 `src/plugins/tabletop/world/`。对话的角色卡是「澜江市」时启用。原因：人物数据和跑团是同一份，插件之间又不能互相引用代码。

| 文件 | 内容 |
| --- | --- |
| `world/city.ts` | 澜江市的数据：区、水系、山、地点、地铁线路、气候 |
| `world/clock.ts` | 日期、星期、天气 |
| `world/route.ts` | 路线、用时、费用 |
| `world/rules.ts` | 规则表：条件、事件、后果 |
| `world/people.ts` | 主角的钱和工作、重要人物的作息、近况、彼此的态度 |
| `world/offscreen.ts` | 不在场的推演、事件表、主动联系 |
| `world/text.ts` | 交给模型的世界数据（按这一幕挑选） |
| `world/entries.ts` | 世界的预设条目 |
| `src/web/components/World*.tsx` | 状态条、事件条、地图、人物、手机、开局页 |

### 预设条目

| 条目 | 标记 | 用在哪里 |
| --- | --- | --- |
| 世界·裁定补充 | `<<<\|hearth\|world-ruling>>>` | 第一步，接在跑团的裁定说明后面 |
| 世界·叙述补充 | `<<<\|hearth\|world-narrate>>>` | 第二步 |
| 世界·结算补充 | `<<<\|hearth\|world-settle>>>` | 第三步 |
| 世界·人物档案说明 | `<<<\|hearth\|world-profile>>>` | 设为重要人物、新建重要人物 |

和跑团的条目一样，由插件取走，不按普通条目发送。

### 工具

世界的对话里，所有请求都声明同样的三个工具，只换强制调用的那一个，这样缓存能共用：

```json
{
  "name": "hearth_check",
  "parameters": {
    "...": "跑团原有的部分",
    "time": { "minutes": 40, "until": "可选：明确的结束时刻，例如 2026-03-03 07:00", "reason": "洗漱、吃早饭，然后出门" },
    "move": { "to": "地点名", "by": "步行 | 骑车 | 地铁 | 公交 | 打车 | 开车", "with": ["一起走的角色"] }
  }
}
```

```json
{
  "name": "hearth_settle",
  "parameters": {
    "...": "跑团原有的部分",
    "world": {
      "extra_minutes": 0,
      "moves": [{ "who": "在场的角色", "to": "地点名" }],
      "money": [{ "amount": -35, "reason": "请林晚喝咖啡" }],
      "appointments": [{ "with": "林晚", "at": "2026-03-06 19:00", "place": "小酌酒馆", "about": "喝一杯" }],
      "cancelled": ["取消的约定"],
      "contacts": ["交换了联系方式的人"],
      "messages": [{ "from": "林晚", "summary": "问你周五有没有空", "replied": true }],
      "places": [{ "name": "旧书店", "near": "钟楼街", "kind": "商店", "about": "老街上的二手书店" }],
```

`hearth_profile` 的参数是第 7 节列出的那些内容。`hearth_setup` 只在开局时用，那时还没有聊天记录，不受缓存的限制。

### 数据存放

| 内容 | 存在哪里 |
| --- | --- |
| 澜江市的地点、交通、气候 | 插件代码里的数据，不存进对话 |
| 世界的实时状态：时间、天气、位置、钱、工作、作息、约定、手机、事件记录、新登记的地点、近况、重要人物之间的态度 | 每个回复版本上，和跑团的实时状态在一起 |
| 重要人物名单和档案 | 对话上（`chat.plugins.tabletop.world`），走修改通道，可以撤销 |
| 开局设置 | 对话上 |
| 主角的介绍 | 这个对话专用的用户角色 |
| 本轮的时间段和事件 | 这条回复消息上，和裁定在一起，所有版本共用 |

每个回复版本存一份完整的实时状态，换版本、开分支时自动切换。为了控制对话文件的大小：事件记录保留 100 条，消息保留 100 条，态度只记互相认识的人。

### 内核需要的支持

1. 插件能新建资源：「澜江市」角色卡、主角的用户角色。
2. 新建对话时由插件接管开局：先不放开场白，显示开局页；开局完成后写入第一条消息，并绑定用户角色。
3. 新的界面：检查器的「地图」「人物」「手机」三页、状态条、事件条。和跑团的界面一样随主程序发布，所以世界玩法要发新版本，不能只靠插件更新。

### 风险

| 风险 | 对策 |
| --- | --- |
| 规则越加越多，互相打架 | 第一期只做第 8 节的规则，每条单独测试，参数放进设置 |
| 模型估计的时间不准 | 路程由程序算；单轮最多 3 小时；结算只能往后推 |
| 正文和程序的状态对不上，例如正文说她回家了，作息说她在上班 | 在场的人以结算为准，不在场的人以程序为准；叙述说明要求按世界数据写 |
| 消息太多，打断剧情 | 每人每天最多主动联系 2 次；主角在忙或睡着时消息留在手机里 |
| 对话文件变大 | 记录有上限；以后改成每个回复版本只存变化 |

### 测试

| 测试什么 | 内容 |
| --- | --- |
| 时间和天气 | 跨天、跨月、星期；每月天气的分布 |
| 路线 | 各种方式的用时和费用；地铁停运；换乘 |
| 规则 | 迟到、旷工、警告、辞退、请假、发工资、房租和欠款、基本开销、熬夜、爽约 |
| 推演 | 按作息定位、心情回落、事件表、两人的交集、主动联系的概率和上限 |
| 挑选 | 交给模型的数据只含这一幕需要的 |
| 整轮 | 用模拟的模型接口跑几天游戏时间：三步、时间段、事件进正文、结算记账、快进 |
| 真实模型 | 用测试密钥跑一个游戏周：时间估计准不准、事件有没有写进正文、每轮的花费 |

## 14. 实现顺序

1. **城市和地图**：澜江市的数据、示意地图、路线计算。
2. **能过日子**：开局、时间和天气、位置和移动、钱和工作、手机，接进跑团的三步。做完这一步，就能扮演一个在澜江市上班的人。
3. **重要人物**：升级、取消、新建，档案，作息和约定，地图上的位置，不在场的推演，主动联系，彼此的态度。
4. **更多规则**：见第 15 节。

## 15. 以后可以做

- **失联和调查**：主角长时间不回消息、不露面，关心他的人先找；48 小时后报警，警方从最后出现的地方查起。重要人物失联也一样。
- **生病**：体质低、淋雨、熬夜时有几率生病，影响属性和工作。
- **节假日和调休**。
- **更多职业**：店主、医生、警察等，各有自己的规则。
- **物品和住处**：随身物品、买东西、搬家。
- **后台步骤用更便宜的模型**，例如结算。
- **每个回复版本只存变化**，减小对话文件。
