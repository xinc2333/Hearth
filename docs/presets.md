# 预设适配

本文说明怎样让一份预设用上 Hearth 的聊天模式、深度思考、纸条和跑团，对应 0.6.0 及之后的版本。

## 原则

- **预设决定发给模型的全部内容。** Hearth 不往提示词里加自己的文字。适配就是在预设的条目里写上 Hearth 认识的标记，以及跑团用的条目。
- **标记在发送前去掉**，不会发给模型。
- **没有适配的酒馆预设照常可用。** 它没有声明的功能，输入框旁就不出现对应的开关：普通的酒馆预设只有「剧场」和「编辑」。
- **预设里的酒馆助手脚本不运行。** 常见脚本的功能由插件直接提供，见[酒馆助手脚本](#酒馆助手脚本)。界面上不提示脚本，所以适配时要确认每个脚本的功能都有着落。

## 回复模式、深度思考和纸条

这三样是 Hearth 自己的开关。预设用条目开头的标记声明「这一条在什么时候发送」：

| 标记 | 这一条什么时候发送 |
| --- | --- |
| `<<<\|hearth\|when:chat>>>` | 只在聊天模式 |
| `<<<\|hearth\|when:theater>>>` | 只在剧场模式 |
| `<<<\|hearth\|when:deepthink>>>` | 只在开着深度思考时 |
| `<<<\|hearth\|when:note>>>` | 只在纸条有内容时 |
| `<<<\|hearth\|when:!deepthink>>>` | 条件前加 `!` 表示相反 |
| `<<<\|hearth\|when:chat,deepthink>>>` | 几个条件同时满足 |

- 预设里有带 `when:chat` 的已开启条目，输入框就出现「聊天」；有 `when:deepthink` 就出现「深度思考」；有 `when:note` 或用到 `{{hearth_note}}` 就出现「纸条」。
- 宏：`{{hearth_note}}` 是纸条的内容，`{{hearth_mode}}` 是 `theater` 或 `chat`，`{{hearth_deepthink}}` 是 `true` 或 `false`。EJS 模板里也能用。
- 聊天模式回复一次后自动回到剧场。纸条随回复送达后自动清空。

例子：

```
<<<|hearth|when:chat>>>
现在暂停剧情。以作者的身份直接回答用户的问题，不要写正文。

<<<|hearth|when:note>>>
用户的场外指示（这一轮优先遵守）：{{hearth_note}}
```

### 自带请求脚本的预设

SPreset 类预设（例如小猫之神）用自己的请求脚本处理这些开关。这类预设不需要上面的标记：只要预设带控制台（条目里有 `<<<|catgodml|enableMenu>>>`）和请求脚本，「酒馆助手」插件就会声明支持这三个开关，并在脚本运行前把开关状态交给它。

## 酒馆助手脚本

酒馆里，预设和角色卡可以带酒馆助手脚本。Hearth 导入时保存这些脚本，但不运行它们。常见脚本要做的事由插件提供：

| 脚本 | 在 Hearth 里 |
| --- | --- |
| SPreset 的加载脚本（注入 `regex_bind/inject.js`） | 「酒馆助手」插件读取预设里的 SPreset 配置，在隔离环境中运行它的请求脚本 |
| SPreset 类预设的控制台菜单（条目里有 `<<<\|catgodml\|enableMenu>>>`） | 回复模式、深度思考和纸条由 Hearth 自己的开关提供；菜单分组在「设置 → 预设」的条目列表里显示 |
| MVU 变量脚本（角色卡） | 「酒馆助手」插件处理 MVU 变量 |

预设里有别的脚本时，适配要把它的功能改写成条目、Hearth 的标记或插件。否则这部分功能不会生效，界面上也不会提示。

## 跑团条目

跑团每轮分三步，每一步的说明都是预设里的一条条目，靠第一行的标记区分：

| 标记 | 用在哪一步 |
| --- | --- |
| `<<<\|hearth\|ruling>>>` | 裁定 |
| `<<<\|hearth\|narrate>>>` | 叙述（写正文） |
| `<<<\|hearth\|settle>>>` | 结算 |
| `<<<\|hearth\|pass>>>` | 开着「检定绝对通过」时，代替检定结果 |
| `<<<\|hearth\|ruling-lead>>>` 等 | 每一步开头的一句话，用预设自己的口吻，见下文 |

- 这些条目不按普通条目发送。跑团把它们取出来，放到对应那一步的请求末尾，后面附上跑团数据。
- 一条条目里可以写几段，每段以一个标记开头。
- 面板「跑团」页的「加到当前预设」会加上一套通用的条目，可以照着改写。

### 每一步怎么接到请求末尾

三步都完整保留预设拼好的请求，只在末尾追加：

- **普通请求**：追加一条消息，角色和条目的角色相同。
- **工具对话**（请求以工具结果结尾，例如小猫之神的请求脚本）：照着已有的格式接着写：先是 `*-lead` 条目里的一句话（可以没有），再调用一次同一个工具，工具结果就是这一步的说明和数据。裁定和结算强制调用跑团的工具，叙述照常用预设的回复工具。
- 三步声明同样的工具，接口有缓存时，后两步能复用前面的内容。

`*-lead` 适合放一段预设口吻的思考，告诉模型接下来要做什么，例如：

```
<<<|hearth|settle-lead>>>
<think>正文写完啦喵！本喵再当一回记账的 DM：调 `context` 读一下结算规则和跑团数据，然后调用 `hearth_settle` 记下变化喵！</think>
<<<|hearth|settle>>>
【结算】……
```

## 例子：小猫之神 2.1.7

适配版保留作者的全部条目、脚本和免责声明，只做了这几处改动：

- 末尾加上四条跑团条目，每条带一句小猫之神口吻的开场（`*-lead`）。
- 条目名称和控制台菜单名称去掉表情符号，例如「活人感加强」原来带一个猫脸表情。
- 回复模式、深度思考和纸条由预设自己的请求脚本处理，不需要另加标记。

小猫之神的作者只允许私下免费传播，所以 Hearth 不附带这份预设，也不附带适配版。

## 检查适配结果

1. 导入预设，在「设置 → 预设」里设为当前预设。
2. 看输入框旁的开关是否和预想的一样。
3. 发一条消息，在面板的「提示词」页看「实际发送」：标记都已去掉，每种模式下发出的条目都对。
4. 跑团：在「提示词」页能看到裁定和结算两步的请求，每一步只在末尾多了内容。
