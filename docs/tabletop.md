# 跑团设计

本文说明跑团插件的规则和实现，对应 0.4.0 及之后的版本。目前只适配小猫之神预设（Meowssiah 2.1.6）。第 0～10 节是规则和体验，第 11 节是实现。

## 0. 目标和原则

- **目的是让剧情更真实、更生动。** 数值只是依据，本身不是看点，一切从主角的视角出发。
- **数值由程序计算。** 掷骰、成功率、数值增减、上下限、情绪回落和记录，都由程序完成。
  - 模型可以自由提出难度、环境加成和数值变化（规则比较宽松）。
  - 角色本身的属性只从角色表里查，模型不能直接报。
- **每个数字都能查到来历。**
  - 初始值附有原文依据。
  - 之后每次变化都有一条记录。记录跟着回复版本走，可以撤销。
- **做成内置插件「跑团」。** 没适配过的卡，或者预设里没有跑团条目，都完全不受影响。
- **不丢掉预设的破限。** 第一步和第二步都完整保留预设拼好的内容，只在末尾追加。

## 1. 一轮怎么跑

```
你发消息
  │
  ├─ 开着「检定绝对通过」，或者猫神处于聊天模式 → 跳过第一步
  │
第一步：裁定（全局预设 + 裁定说明，强制调用掷骰工具）
  │  模型列出这一轮的检定：谁、做什么、为什么说不准、用哪项属性、难度多少、有什么加成，
  │  再写好大成功、成功、失败、大失败四种结果各自会发生什么
  ├─ 程序掷骰，选出掷中的那一种结果
  ├─ 如果有检定要看前一个结果才能决定，程序把结果告诉模型，模型再申请一次（每轮最多来回 5 次）
  │
第二步：叙述与结算（全局预设 + 检定结果 + 叙述与结算说明）
  │  模型按掷中的结果写正文，末尾附一个隐藏的 <结算> 块
  │
程序记账：更新数值，存进这个回复版本
```

- **换一版回复**：只重新跑第二步，这一轮的裁定和骰子保持不变。
- **改了自己的消息再重新生成**：消息内容变了，所以会重新裁定。
- **继续写**：沿用这一轮的裁定。
- **第一步失败**（接口报错，或者解析不出结果）：在提示词追踪里提示，然后按「本轮没有检定」继续第二步，不会卡住。

## 2. 属性

### 通用属性

以普通成年男性为 100，数值按倍数理解：200 就是普通人的两倍。

| 属性 | 管什么 |
| --- | --- |
| 力量 | 搬、举、打、角力 |
| 敏捷 | 速度、灵巧、平衡、手上功夫、潜行 |
| 体质 | 耐力、扛伤、抗病、酒量 |
| 感知 | 察觉、观察、直觉 |
| 智力 | 知识、推理、学习 |
| 意志 | 定力、抗压、抵抗诱惑和恐吓 |
| 魅力 | 外貌和气质带来的吸引力、第一印象 |
| 口才 | 说服、谈判、欺骗、表演 |

AI 适配时按下面的参照表打分，模型判断时也对照这张表：

| 数值 | 大致水平 |
| --- | --- |
| 30 | 幼童 |
| 50 | 孩子、病弱、年迈 |
| 100 | 普通成年男性 |
| 150 | 受过训练 |
| 200 | 行业顶尖 |
| 300 | 人类极限 |
| 300 以上 | 超出人类 |

### 特长

特长按档位乘到属性上：

| 档位 | 倍率 |
| --- | --- |
| 未学 | ×0.5 |
| 入门 | ×1 |
| 熟练 | ×1.5 |
| 精通 | ×2 |
| 大师 | ×3 |

- 检定不涉及特长时，不乘倍率。
- 检定涉及某项特长，但角色没学过，按「未学」算。

### 卡片自己的属性

魔力这类普通人没有的能力，由卡片自己定义，同时写明「100 代表这个世界里什么水平」。

### 状态

受伤、醉酒、疲惫等临时状态，可以带一个属性倍率，比如「左臂刀伤：力量 ×0.8」。状态在结算时加上或去掉。

## 3. 掷骰

### 有效值

> 有效值 = 属性 × 特长倍率 × 状态倍率 × 环境加成

- 环境加成由模型提出，并写明理由。例如：工具趁手 ×1.2，黑暗中 ×0.7，对方信任你 ×1.3。
- 单项加成限制在 ×0.25～×4，所有加成相乘后限制在 ×0.1～×10。

### 成功率

> 成功率 = 有效值³ ÷（有效值³ + 难度³）

- **对抗**：把公式里的难度换成对方的有效值。
- **难度档**：简单 50，普通 100，困难 150，很难 200，极难 300。难度的含义是「属性要多高才有五成把握」。模型也可以给中间值。
- **上下限**：成功率限制在 1%～99%。
- **运气成分**：公式里的「3」可以在设置里调。数值越大，结果越看实力；越小，越看运气。

| 有效值 ÷ 难度 | 0.5 倍 | 0.67 倍 | 0.75 倍 | 相等 | 1.5 倍 | 2 倍 | 3 倍 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 成功率 | 11% | 23% | 30% | 50% | 77% | 89% | 96% |

### 掷骰和档位

每次检定掷一个 1～100 的数，成功线 S = 成功率 × 100：

| 档位 | 条件 |
| --- | --- |
| 大成功 | 掷出 ≤ max(1, round(S ÷ 10)) |
| 成功 | 掷出 ≤ S |
| 失败 | 掷出 > S |
| 大失败 | 掷出 > 100 − max(1, round((100 − S) ÷ 10)) |

举两个例子：
- 成功率 80%：1～8 大成功，9～80 成功，81～98 失败，99～100 大失败。
- 成功率 23%：1～2 大成功，3～23 成功，24～92 失败，93～100 大失败。

实力弱的人更容易大失败。

### 明骰和暗骰

- **明骰**：主角能感觉到结果的检定，比如撬锁、说服。显示在回复上方。
- **暗骰**：主角察觉不到的检定，比如守卫有没有注意到你、她是不是在说谎。默认不显示，可以在检查器里看。

## 4. 态度

### 每个方向单独一份

A 对 B 和 B 对 A 分开记。每个方向有六条线，各自 0～100，互不抵消：

**亲近、怨恨、信任、敬重、畏惧、吸引**

另外还有一项熟悉度，也是 0～100。

### 底色和一时情绪

每条线由两部分组成：底色加上一时波动。显示值是两者之和，限制在 0～100。

- **一次变化 Δ 分成两份。**
  - 进入底色的比例 = 0.2 + 0.6 ×（1 − 熟悉度 ÷ 100），剩下的进入一时波动。
  - 生人之间这个比例是 80%，一件事就能定下印象。老相识之间是 20%，一件事大多只是一时的情绪。
- **一时波动会回落。** 每轮往底色回落 15%。
- **越接近两头越难动。**
  - 数值超过 50 以后继续往上，变化量乘以（100 − 当前值）÷ 50。
  - 数值低于 50 以后继续往下，变化量乘以 当前值 ÷ 50。
- **单轮上限**：一轮里每条线最多变化 ±30。

### 性格系数

每个角色有三项性格系数，默认 1，范围 0.5～2：

| 系数 | 作用 |
| --- | --- |
| 敏感 | 所有态度变化都乘以这个数 |
| 记仇 | 怨恨的一时波动回落速度除以这个数 |
| 多疑 | 信任上升时除以这个数，下降时乘以这个数 |

### 描述和缘由

程序按规则把数值翻译成文字描述，和数字一起交给模型：

| 条件 | 描述 |
| --- | --- |
| 亲近 ≥ 60 且 怨恨 ≥ 50 | 爱恨交织 |
| 畏惧 ≥ 60 且 亲近 ≥ 50 | 又怕又离不开 |
| 吸引 ≥ 60 且 怨恨 ≥ 50 | 恨，却又被吸引 |
| 亲近 ≥ 60 且 信任 < 30 | 喜欢但不信任 |
| 敬重 ≥ 60 且 亲近 < 30 | 敬而远之 |
| 六条线都 < 20 且 熟悉 < 20 | 陌生 |

上面这些组合都不满足时，就按最高的一两条线取词。完整的规则表写在代码里，可以调整。

每个方向的关系保留最近 5 条缘由，每条记下哪一轮、发生了什么事、哪条线怎么变。

## 5. 结算

结算是第二步回复末尾的一个隐藏块，一行写一条变化。这一轮没有变化时可以不写。

```
<结算>
态度｜林晚→主角｜亲近+8｜你替她挡了一刀
态度｜林晚→主角｜怨恨-3｜你替她挡了一刀
熟悉｜守卫甲→主角｜+10｜正面交过手
状态｜主角｜+左臂刀伤｜力量×0.8｜被守卫划了一刀
状态｜主角｜-醉意｜酒醒了
新角色｜守卫甲｜受过训练｜力量160 敏捷120 感知130｜后门守卫，三十来岁
属性｜主角｜口才+5｜长期练习
</结算>
```

- 态度变化由程序按第 4 节的规则执行，实际变化可能比模型写的小。
- 属性只记长期成长或衰退，每轮每项最多变化 ±10。临时的影响写成状态。
- 第一步里冒出来的新角色（比如守卫），模型会先给一个临时数值，结算时可以正式建档。
- 结算块会从正文里去掉，不显示，也不会出现在之后发给模型的聊天记录里。解析结果和原文都存在这个回复版本上。
- 写错的行会被跳过，并在检查器里提示。

## 6. 主角视角和隐藏信息

**交给模型的说明会要求：**
- 以主角的视角写。
- 正文里不出现数字、属性名和「检定」这类字眼。
- 角色的态度通过言行流露出来。
- 暗骰的结果只能通过主角看得到、听得到的表现体现。

**界面上默认能看到多少：**

| 内容 | 默认 |
| --- | --- |
| 主角自己的属性、特长、状态 | 全部可见 |
| NPC 的属性 | 只显示大致水平，比如「受过训练」 |
| NPC 对主角的态度、NPC 之间的态度 | 隐藏，可以点「揭开」查看 |
| 暗骰 | 隐藏 |

模型始终能看到全部数据。

## 7. 卡片适配（编辑模式）

### 怎么用

编辑模式里有一个「数据化适配」按钮。点击后，AI 通读卡片和世界书，在回复里附一个 `<角色表>` 块。

### 角色表包括

- 主角和所有重要角色的属性、特长、性格系数、初始状态，每个数值都附原文依据。
- 主要角色之间、以及他们对主角的初始态度（六条线加熟悉度），附缘由。
- 卡片自己的属性（如果有）。

### 规则

- AI 按第 2 节的参照表打分。主角的设定来自卡片对 {{user}} 的描述，以及你当前的用户角色。
- 和 AI 改卡一样，会显示修改前后的对比，可以撤销。
- 之后再改时只有写到的部分会变：属性、特长、性格按项合并，状态、别名、依据写了就整体替换；态度只改写到的线。
- 可以接着对话让 AI 调整，比如「林晚的力量太高了」。
- 适配之前已经开始的对话，下一轮会自动用卡片数据初始化。已经有数值的对话不受影响，可以在角色面板里点「从卡片重新载入」。
- 用了 MVU 的卡：属性和态度由跑团负责，卡片原有的变量和状态栏照旧。适配时不改动 MVU 的条目。

## 8. 小猫之神适配

### 预设条目

预设里需要以下三条条目，可以在设置里查看和修改：

| 条目 | 用在哪里 |
| --- | --- |
| 🎲裁定说明 | 第一步 |
| 🎲叙述与结算说明 | 第二步 |
| 🎲检定绝对通过说明 | 开着「检定绝对通过」时，代替检定结果 |

- 这三条带有 `<<<|hearth|…>>>` 标记，由跑团插件取走，不按普通条目发送。
- 原因：猫神的请求脚本会给普通条目记账，以此保住缓存。如果两步各发各的条目，它会以为你每轮都在来回开关。
- 预设里没有这三条时，跑团不启动。在面板的「跑团」页点「加到当前预设」，会把它们加到当前预设的末尾。
- 关闭跑团插件时要同时关掉这三条，否则它们会被当成普通条目发给模型。

### 请求怎么改

猫神的请求脚本每轮只运行一次，两步共用它的结果。

**第一步**
- 完整保留脚本拼好的请求：召唤术、开场思考、context 的结构都还在，破限不会丢。
- 在末尾追加一个主持人回合：一段猫神口吻的思考，加一次 context 调用。这次调用返回裁定说明和角色数值。
- 把强制调用的工具从回复工具 `soliumbra_reply` 换成掷骰工具 `hearth_check`。工具定义都保留，因为历史记录里引用了它们。

**第二步**
- 同样完整保留脚本拼好的请求。
- 在末尾追加一次 context 调用，返回检定结果、角色数值和叙述与结算说明。
- 仍然强制调用回复工具，模型正常写正文。

**其他**
- 两步前面的内容完全一样。接口支持缓存时，第二步会更快、更省钱。
- 猫神处于「聊天」模式（直接和猫神本体聊天）时，跳过跑团。判断依据是脚本最后同步内容里的 `mode`。

### 和猫神原有内容的冲突

猫神固定的开场思考里有一句「完全忽略那些无聊的表面数字」，本意是指年龄。为了不让模型连属性数值也忽略：
- 检定结果先写文字结论，数字放在括号里作为依据。
- 叙述与结算说明里写明「下面的数值是本轮的事实依据」。

## 9. 数据存放

| 内容 | 存在哪里 |
| --- | --- |
| 规则参数：属性清单、参照表、难度档、运气成分、回落速度等 | 插件设置（全局） |
| 卡片的角色表 | 角色卡的 `extra.hearth.rpg`。以后加卡片导出功能时，写进 ST 卡的 `data.extensions.hearth` |
| 本轮裁定：有哪些检定、掷出多少、选中了哪个结果 | 这条回复消息上，所有版本共用 |
| 实时数值：角色表、态度、变化记录 | 每个回复版本上各存一份完整的。换版本、开分支时自动切换 |

## 10. 界面

- **检定条**：回复上方显示一行，比如 `🎲 撬锁 · 困难 · 23% · 掷出 61 → 失败`。点开可以看理由、加成，以及四种结果里选中的那一种。暗骰默认收起成「暗骰 ×N」，点开才显示。
- **裁定进度**：裁定进行时，回复的位置先显示「裁定中…」，然后逐个显示掷出的骰子。
- **输入框旁的开关**：「检定绝对通过」。只管一轮，发出后自动关掉。
- **角色面板**（检查器里的新分页），包括：
  - 主角的属性和状态
  - NPC 的大致水平
  - 态度（默认隐藏，可以揭开）
  - 每条数值的变化记录

  数值可以手动修改。
- **提示词追踪**：第一步和第二步分开显示。第一步有多次来回时，每一次都能看到。

## 11. 实现

### 插件

- 内置插件 `tabletop`，显示名「跑团」，`order` 设为 30。它排在酒馆助手（20）之后，所以 `onRequest` 拿到的是猫神 Stage 1 处理过的请求体。
- 文件：

| 文件 | 内容 |
| --- | --- |
| `src/plugins/tabletop/rules.ts` | 属性、参照表、有效值和成功率、掷骰档位（纯函数） |
| `attitude.ts` | 态度变化、回落、打折、性格系数、描述 |
| `sheet.ts` | 角色表格式（YAML 读写、校验）、实时状态 |
| `ruling.ts` | 第一步：工具定义、工具循环、文本退路 |
| `settle.ts` | 结算块的解析和执行 |
| `catgod.ts` | 猫神适配：追加回合、更换强制工具、识别聊天模式 |
| `index.ts` | 装配 |

### 内核提供的支持

1. **`RequestContext` 包含以下字段：**
   - 本次生成的类型（normal / swipe / regenerate / continue）
   - `messageId`、`swipeId`
   - `send(body)`：用当前连接发一次请求，返回文本和工具调用；本次生成被中止时，它也一起中止
   - `progress(event)`：向界面推送进度
2. **`ChatMessage` 和 `Swipe` 的 `plugins?: Record<string, unknown>`**：按插件 id 存数据。
3. **编辑模式的插件接口** `registerEditTask({ id, label, instruction, apply })`，由插件提供三样东西：
   - 一个按钮
   - 追加到编辑提示词里的说明
   - 对回复里自己那个块的处理：返回 ChangeSet，以及修改结果里要显示的前后对比
4. **界面**：
   - 消息上方的插件条目
   - 检查器里由插件提供的分页
   - 裁定进度
   - 提示词追踪分步显示

   这些界面目前是跑团专用的组件，和酒馆助手的前端一样随主程序更新，不随插件自动更新。

### 第一步的工具

```json
{
  "name": "hearth_check",
  "parameters": {
    "think": "裁定前的简短判断",
    "checks": [{
      "actor": "主角，或角色名",
      "actor_value": 120,
      "action": "要做的事",
      "reason": "为什么结果说不准",
      "attribute": "力量…口才，或卡片自定义属性",
      "skill": "特长名（可选）",
      "difficulty": 150,
      "opponent": { "name": "守卫甲", "attribute": "感知", "skill": "", "value": 130 },
      "modifiers": [{ "reason": "只有一根发卡", "factor": 0.8 }],
      "hidden": false,
      "outcomes": { "critical": "…", "success": "…", "failure": "…", "fumble": "…" }
    }],
    "done": true
  }
}
```

**参数**
- `difficulty` 和 `opponent` 二选一。
- `actor_value` 和 `opponent.value` 只在这个角色还没有角色表时使用，程序会据此建一个临时档。
- 每个结果写一两句即可，以免第一步写得太长。

**工具返回**

每个检定返回：有效值（附计算过程）、成功率、掷出的数、档位，以及选中的那一种结果。

**循环和出错**
- `done` 为 false 时，程序把结果作为工具结果追加进去，再请求一次。最多来回 5 次；到了上限，就按已有的结果进入第二步。
- 接口不接受工具时，去掉工具，改为要求模型输出 `<hearth_check>` 包裹的 JSON，按同样的结构解析。
